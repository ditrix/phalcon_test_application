# 3. Промпт: RowNormalizer и тесты

> Новый чат. Предыдущий шаг (2) должен быть проверен.

## Промпт

Прочитай `AGENTS.md`, разделы 3 и 5. **Шаг 2 из 8: нормализация строк.**

Создай `app/Services/RowNormalizer.php` — **чистый класс без БД, без Phalcon, без I/O**, совместимый с PHP 7.2.

**Интерфейс:**

```php
public function normalize(array $csvRow, int $rowNo): NormalizedRow
```

`$csvRow` — массив из 15 значений в порядке колонок CSV (см. раздел 3 AGENTS.md). Верни простой объект/массив: `fields` (ассоциативный, готов для INSERT: все 15 колонок + `row_no`), `warnings` (массив кодов), `fatal` (null или строка с причиной).

**Правила** (раздел 5 AGENTS.md, таблица «Normalization»):
- Для любой строки: `trim`, удаление BOM `\xEF\xBB\xBF` в начале значения, пустая строка → `NULL`.
- `phone`: оставить только цифры (это убирает `.0` и `#ERROR!`); валиден, если ровно 12 цифр и начинается с `380`; иначе `NULL` + `phone_invalid`. Внимание: значение `380672341057.0` — после удаления нецифровых символов получится `3806723410570` (13 цифр). Поэтому **сначала** отрезай хвост `.0` (регуляркой `/\.0+$/`), и только потом чисти нецифровые символы.
- `email`: `trim`, `strtolower`, `filter_var(FILTER_VALIDATE_EMAIL)`; невалидный → `NULL` + `email_invalid`. Пустой — не предупреждение, просто `NULL`. Ничего не «чини» (`@@` не исправлять).
- `budget_uah`: убрать пробелы и NBSP (`\xC2\xA0`), запятую как десятичный разделитель не поддерживать; привести через float (для `1.2E+15`); целое неотрицательное в пределах BIGINT UNSIGNED, иначе `NULL` + `budget_invalid`. Пустой → `NULL` без предупреждения. Осторожно с точностью float для больших значений — реши и объясни.
- `created_at`, `next_contact_at`: формат `Y-m-d H:i:s` ИЛИ Excel serial (число с точкой, например `45848.213125`). Результат `Y-m-d H:i:s`. Формула serial: `(int) round(($serial - 25569) * 86400)`, `gmdate`. `next_contact_at` невалидный → `NULL` + `date_invalid`. `created_at` пустой/невалидный → `fatal`, потому что колонка NOT NULL.
- `external_id`: пустой → `fatal` (`external_id_missing`).
- Остальные строки: обрезать `mb_substr` до длины колонки (first_name/last_name/city/source/utm_campaign/product/manager 100, email 150, phone 20, status 50, external_id 32).
- Если колонок в строке не 15: дополни `NULL` справа, если меньше; если больше — лишнее отбрось; в обоих случаях warning `column_count_mismatch`. Строка из одного пустого поля = пустая строка CSV → верни специальный признак «skip».

**Тесты:** `tests/RowNormalizerTest.php`. Без зависимостей: простой скрипт на `assert`-ах и понятный вывод PASS/FAIL, запускаемый `docker compose exec web php tests/RowNormalizerTest.php` (код выхода 1 при провале). Обязательные кейсы на реальных значениях из файла:
- phone: `380672341057`, `380672341057.0`, `#ERROR!`, `12345`, `380`, `""`
- email: `user@@ukr.net`, `ivan.hrytsenko386gmail.com`, `oleksandr.marchenko822@`, `Valid@Example.COM`, `""`
- budget: `"23 700"`, `"23\xC2\xA0700"`, `23700.0`, `1.2E+15`, `""`, `-5`, `abc`
- даты: `2025-07-10 05:06:54`, `45848.213125`, `""`, `garbage`
- BOM в `external_id`, пустой `first_name`, длинная строка > 100 символов.

**Не делай:** чтение файлов, запись в БД, выбор пакетов.

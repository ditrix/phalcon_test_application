# 4. Промпт: потоковый CSV-импорт и CLI-бенчмарк

> Новый чат. Шаги 2 и 3 проверены.

## Промпт

Прочитай `AGENTS.md`, разделы 4 и 5. **Шаг 3 из 8: CsvImporter + замер скорости. Без UI.**

Реши главный риск задания: 100 000 строк за время < 30 с, а лучше намного быстрее.

**Создай:**

1. `app/Services/ImportRepository.php` — весь SQL в одном месте (сырой SQL, без ORM):
   - `createImport(...)`, `updateImport(...)`, `getImport($id)`;
   - `insertBatch($importId, array $rows)` — **один multi-row INSERT** на пачку (плейсхолдеры/bind, без конкатенации значений в SQL);
   - позже понадобятся `markDuplicates($importId)`, статистика и постраничный список — пока сделай `markDuplicates` одним SQL `UPDATE ... JOIN`: для каждого `external_id` строка с минимальным `row_no` внутри импорта остаётся `is_duplicate=0`, остальные `1`.
2. `app/Services/CsvImporter.php`:
   - `fopen` + `fgetcsv` (потоково, не грузить файл в память); удалить BOM в начале файла; первую строку — заголовок — проверить на совпадение с 15 ожидаемыми колонками (имена, регистр игнорировать), несовпадение — понятная ошибка;
   - использовать `RowNormalizer` из шага 3;
   - накапливать пачку (константа, 1000 строк), вставлять в транзакции (`begin/commit/rollback`);
   - **метод с возобновлением:** `run(int $importId, int $timeBudgetSeconds): array`. Читает с `byte_offset` из таблицы `imports` (`fseek`), обрабатывает строки, пока не закончился файл или не вышел бюджет времени (проверка `microtime(true)` между пачками), после каждой пачки сохраняет в `imports` `byte_offset` (`ftell`), `rows_read`, `rows_inserted`, счётчики warnings (JSON), возвращает состояние (`done` или `importing`). Номер строки `row_no` должен быть сквозным и продолжаться после возобновления;
   - fatal-строки не вставляются, а считаются и фиксируются (в `imports.error` или отдельный счётчик — выбери и объясни; в статистике они должны быть видны);
   - `ftell` после `fgetcsv` корректен, только если читаешь строки по одной; убедись, что при возобновлении нет потери или дублирования строки на границе (напиши тест/проверку на этом).
3. `cli/import.php <path.csv>`: создаёт запись в `imports`, запускает импорт **одним вызовом без лимита времени** и печатает: количество прочитанных/вставленных строк, количество дублей, warnings по кодам, затраченное время, пик памяти (`memory_get_peak_usage(true)`).
4. Вариант `cli/import.php <path.csv> --budget=2` — режим с малым бюджетом времени, который доказывает возобновление: скрипт сам повторяет вызовы `run()`, пока не `done`, и печатает число итераций.

**Не делай:** работу с xlsx, HTTP-эндпоинты, UI, ORM, `set_time_limit`.

**Критерии готовности** (запускай сам и показывай результат):
```bash
docker compose exec web php cli/migrate.php
docker compose exec db mysql -uphalcon -psecret phalcon_app -e "TRUNCATE requests; TRUNCATE imports;"
docker compose exec web php cli/import.php /var/www/html/docs/База_даних_-_Аркуш1.csv
docker compose exec db mysql -uphalcon -psecret phalcon_app -e "SELECT COUNT(*), SUM(is_duplicate), SUM(warnings IS NOT NULL) FROM requests;"
```
- `COUNT(*) = 100000`, `SUM(is_duplicate) = 205` (поправь, если фактическое число после проверки другое, и объясни).
- Время одной итерации (весь файл) — в отчёте. Ориентир: < 15 с.
- Режим `--budget=2` даёт то же число строк в БД (после TRUNCATE), без потерь и дублей на границах.

Если время превышает 20 секунд, не оптимизируй вслепую: покажи профиль (время чтения, нормализации, вставки отдельно) и предложи варианты (размер пачки, `unique_checks`/индексы, `autocommit`, и т.д.).

# 7. Промпт: страница импорта (Tailwind + JS)

> Новый чат. API (шаг 6) работает и проверено через `curl`.

## Промпт

Прочитай `AGENTS.md`, разделы 1 и 8. **Шаг 6 из 8: UI.** Бэкенд уже работает, меняй его только если найдёшь реальную ошибку (и сообщи об этом).

**Страница `GET /`** — один HTML-файл (`app/views/index.php`), Tailwind через CDN, чистый JavaScript (`fetch`), без сборки и фреймворков. Три состояния на одной странице, переключаются без перезагрузки.

**1. Форма выбора файла**
- Выбор файла (`accept=".csv,.xlsx"`), drag & drop по желанию.
- Показ имени и размера выбранного файла, кнопка «Импортировать» (disabled без файла).
- Клиентская проверка расширения и понятное сообщение об ошибке.

**2. Процесс**
- Загрузка (`fetch POST /import/upload` с `FormData`; если нужен прогресс загрузки — `XMLHttpRequest` с `upload.onprogress`, объясни выбор).
- Затем цикл вызовов `POST /import/step`, пока `status !== 'done'`. Между вызовами обновлять прогресс-бар (`percent`), счётчики «прочитано / вставлено», текущий этап (загрузка → конвертация xlsx → импорт → завершение), таймер.
- Лёгкая анимация (плавный прогресс-бар, спиннер). Без тяжёлых библиотек.
- Ошибки сети и серверные ошибки: показать сообщение и кнопки «Повторить» (продолжить цикл `step` для того же `import_id`, он умеет возобновляться) и «Начать заново».

**3. Результат**
- Карточки статистики из `GET /import/{id}/stats`: всего строк, вставлено, дублей, строк с предупреждениями, fatal-строк, время, исходный формат. Отдельный блок «предупреждения по типам» (`phone_invalid: N` и т.д.).
- Таблица из `GET /import/{id}/rows`: серверная пагинация (50 на страницу), номера страниц с многоточием (для 2000 страниц не рисовать все), «в начало / в конец». Колонки: row_no, external_id, created_at, имя, телефон, email, город, статус, бюджет, менеджер. Бейджи: «дубль» и «warnings» (с кодами). Фильтр: все / дубли / с предупреждениями.
- Кнопка «Новый импорт».
- Пустые значения (`NULL`) показывать как «—».

**Требования:**
- **Весь вывод экранировать** (в данных произвольный текст): используй `textContent` либо функцию `escapeHtml`; никакого `innerHTML` с данными без экранирования.
- Адаптивная вёрстка, аккуратный современный вид, без лишних декоративных элементов.
- Состояние страницы сохраняй в одном объекте JS; код организуй небольшими функциями (`renderProgress`, `renderStats`, `loadRows` и т.п.), без глобального беспорядка.
- Доступность: у кнопок и прогресса `aria`-атрибуты, фокус-состояния.

**Не делай:** фреймворки (React/Vue), Node-сборку, изменение схемы БД, авторизацию.

**Критерии готовности:** я открываю `http://localhost:8080/`, выбираю CSV, вижу прогресс и итоговую статистику, листаю таблицу; повторяю с XLSX. Опиши ручной тест-план из 8-10 пунктов (включая отмену, неверный тип файла, обрыв сети — например, остановка контейнера `db` посреди импорта — и «Повторить»).

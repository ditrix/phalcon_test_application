# 5. Промпт: потоковая конвертация XLSX → CSV

> Новый чат. Шаг 4 (CSV-импорт) должен работать и быть замерен.

## Промпт

Прочитай `AGENTS.md`, разделы 3 и 5. **Шаг 4 из 8: XlsxToCsvConverter.**

Файл `База_даних.xlsx` весит 26 МБ (100 000 строк). PhpSpreadsheet и подобные библиотеки сюда **не подходят** (память и время). Нужен потоковый разбор «вручную».

**Создай `app/Services/XlsxToCsvConverter.php`:**

1. Открыть xlsx через `ZipArchive`. Нужные части: `xl/workbook.xml` (первый лист), `xl/_rels/workbook.xml.rels` (найти путь к листу; допускается упрощение `xl/worksheets/sheet1.xml`, но проверь и обработай случай, когда файла нет), `xl/sharedStrings.xml`, `xl/styles.xml` (для определения, какие ячейки — даты).
2. **sharedStrings:** прочитай потоково через `XMLReader` в массив (индекс → строка). Учти `<si><t>` и rich text `<si><r><t>`. Оцени потребление памяти для ~100k строк и сообщи.
3. **Лист:** `XMLReader` по `sheet1.xml`, читай по одной `<row>`, внутри `<c r="A1" t="s|n|str|inlineStr|b|e" s="...">`. Правильно размести значения по колонкам по ссылке `r` (пропущенные пустые ячейки должны давать пустые значения, а не сдвигать колонки). Записывай строку в CSV через `fputcsv` (UTF-8, без BOM, разделитель запятая).
4. **Формат значений:**
   - строки из sharedStrings — как есть;
   - числа записывать как есть, **без научной нотации и без потери точности**: например `23700.0` останется `23700.0` (нормализатор разберёт), телефон `380672341057` не должен превратиться в `3.80672341057E+11`. Проверь, как значение лежит в XML (`<v>`), и возвращай его строкой из XML без `(float)` приведения;
   - даты: в файле `created_at` и `next_contact_at` лежат как serial-числа (`45848.213125`). Не пытайся угадывать по стилям, просто оставь число — `RowNormalizer` уже умеет Excel serial (шаг 3). Но проверь, что число не округлено;
   - ошибки `t="e"` (`#ERROR!` и т.п.) — как текст значения.
5. Результат: путь к временному CSV в `storage/uploads/`; первая строка — заголовок. Верни статистику (число строк, время).
6. `cli/convert.php <file.xlsx>` — печатает время, пик памяти, число строк, путь результата.

**Критерии готовности:**
- `docker compose exec web php cli/convert.php docs/База_даних.xlsx` — время и пик памяти в отчёте. Память должна быть умеренной (ориентир < 128 МБ).
- Сравни результат с оригинальным CSV: число строк совпадает (100 000 + заголовок), первые 5 и последние 5 строк совпадают по значениям с точностью до формата (даты — serial, бюджет — `23700.0`). Покажи diff для нескольких строк.
- Прогони `cli/import.php` на сконвертированном CSV: итог в БД должен совпасть с импортом исходного CSV (100 000 строк, 205 дублей).

**Главный вопрос — время.** Конвертация должна уложиться в 30 секунд **в одном HTTP-запросе**. Если твой замер больше ~20 с — НЕ придумывай обходных путей молча. Покажи цифры и предложи варианты, например: оптимизация (убрать лишние аллокации), возобновляемая конвертация (перечитывание XML с пропуском N строк), либо запуск конвертации отдельным CLI-процессом (`exec` в фоне, у CLI нет `max_execution_time`), чем-то из этого пожертвовав. Решение я приму сам.

**Не делай:** PhpSpreadsheet/Spout и другие зависимости, HTTP-эндпоинты, UI.
